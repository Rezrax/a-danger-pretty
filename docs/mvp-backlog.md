# Night City Agent — Backlog

## MVP Planning

The [README roadmap](../README.md#development-roadmap) defines the implementation order. MVP stories and acceptance criteria are still being refined from [product-requirements.md](product-requirements.md). This file is not yet a complete MVP backlog.

## Post-MVP Features

### FUTURE-01 — Datashard Encryption Minigame (MVF)

**Status:** Backlogged; explicitly outside MVP.

**Priority label:** MVF — Maximum Valued Feature.

**Player experience:** Solve an in-world encryption puzzle to unlock and read a datashard, adding an interactive discovery moment to a GM handout.

**To design later:** Puzzle mechanics, difficulty, hints, GM controls, and whether unlocking applies individually or to a group. No real cryptographic system is implied by this narrative feature.

The MVP continues to use plain-text datashards without an unlocking minigame.

### FUTURE-02 — Player Contact Sharing

**Status:** Post-MVP; very low priority, below the encryption minigame.

**Player experience:** Share an existing contact with another player so they can add it to their contacts.

**Rationale:** The GM can establish contacts before session 1 and manage them during MVP. Expected value after session 1 is low, so this should not delay core work.

**To design later:** Recipient acceptance, which profile information is shared, and contact-addition permissions. MVP contact changes remain GM-only.
